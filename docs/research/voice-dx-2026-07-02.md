# Speko Voice CLI — Agent-First DX Research Report

**Scope:** Bek's 5 asks (clone, tags, failover, costs, speech diagram) for `@spekoai/mcp-calls` v0.4.7, evaluated for coding-agent consumers. Grounded in the platform monorepo (`~/SpekoAI-platform`), installed SDK (`@spekoai/sdk@0.4.3`), this repo, and external prior art. No code changed, no credits spent.

---

## 1. TL;DR

Four of Bek's five asks are **surface work over platform APIs that already exist** — the platform has a complete voice-clone REST API with dashboard UI, a fully authored per-model emotion-tag capability registry, benchmark-ranked failover with per-attempt telemetry, per-call cost in the ledger, and per-turn + word-level timing data. Almost none of it reaches the SDK or CLI: the SDK has no clone resource, `/v1/voices` strips capability flags, the SDK drops the `X-Speko-First-Byte-Ms` header, route-level speak/transcribe return zero cost, and word timestamps are dropped at the batch transcribe route. For coding agents every one of these is a **JSON contract, not a UI** — Anthropic's own code-execution numbers (98.7% token savings keeping intermediates out of context) validate the existing CLI-with-`--json` + file-artifact architecture as the right agent interface. The three highest-leverage moves: **(1)** ship `speko usage` / `speko credits` / `speko call report` (cost + per-turn timing) this week with zero platform changes — the SDK already types all of it; **(2)** get two surgical platform changes accepted — serialize per-model capabilities in `/v1/voices` (~1 line) and an `X-Speko-Cost-Micro-Usd` + request-id header on synthesize/transcribe (cost is already computed before the stream closes); **(3)** add a `VoiceClones` SDK resource wrapping the existing 7-endpoint API into one consolidated, **consent-gated, human-only** CLI command — and permanently exclude clone-creation from the MCP tool surface as a documented design decision.

## 2. Feature-by-Feature

### 2.1 Voice Clone

**WHAT EXISTS**
- `EXISTS-platform-only` — Complete mounted REST surface: POST/GET/DELETE `/v1/voice-clones`, clip register → GCS signed PUT → finalize, provision-targets, provision/unprovision with BYOK-else-MANAGED key resolution (`apps/server/src/routes/voice-clones.ts:1-24`, `:642-885`; mounted `main.ts:790`). 968-line route file; full dashboard UI (`apps/dashboard/src/app/(dashboard)/voices/` — clip-composer, new-clone flow, per-voice page).
- `EXISTS-platform-only` — Three wired clone targets with capability constraints: ElevenLabs (1-25 samples, 60-180s), Cartesia (1 clip, 10-20s), MiniMax (1 clip ≥10s, GroupId-scoped key); OpenAI/Deepgram/Polly/Azure/Google deliberately excluded (`packages/core/src/lib/types/voice-clone.ts:37-68`). Adapter contract returns a `providerVoiceId` that is exactly what `TtsConfig.voice` takes (`packages/core/src/lib/interfaces/voice-cloning-provider.ts:29-55`).
- `MISSING (SDK)` — Zero clone symbols in `@spekoai/sdk` (verified by grep of installed dist resources this session and platform `packages/sdk/src`); Voices is read-only `list()`. `GET /v1/voices` is a static catalog that never merges org clones (`apps/server/src/routes/voices.ts` — catalog-only).
- `MISSING (platform)` — **Clones are an island:** synthesize passes a raw provider voice string, no clone-name → provider-voice-id resolution; agent/call path has zero `voice_clone` references (`apps/server/src/routes/synthesize.ts:48,327`). A cloned voice pins you to one provider and **silently breaks under Speko's own failover** — even though `voice_clone_provision` (one provider-native id per provider, `db/schema.ts:1830-1966`) is exactly the mapping failover would need.
- `MISSING (platform)` — **Zero consent gating:** `createCloneSchema` is just `{name, description?, language?}` (`voice-clones.ts:96-100`); no attestation field, no consent copy in the dashboard. The in-house pattern to mirror exists: `demo_call` stores `terms_accepted_at` + turnstile hash + IP "as a defensible record" (`db/schema.ts:321-357`).
- `UNVERIFIED` — Whether the clone surface is live in prod: `GCS_VOICE_CLIPS_BUCKET` empty disables clip upload/provisioning (`env.ts:87`); config state not checked. Also unverified: whether MANAGED MiniMax keys are GroupId-scoped (i.e. whether managed MiniMax cloning works at all).

**COMPETITOR BENCHMARK** — ElevenLabs: IVC via SDK only (no consent param, ToS-level); PVC is **self-voice-only with a spoken voice-captcha** — strongest anti-impersonation design shipping. Cartesia (what Speko uses): ~3s instant clone, no technical verification, consent lives in the AUP only. OpenAI never publicly shipped Voice Engine over impersonation risk. No major provider ships cloning as a first-class CLI command — `speko voices clone` would be novel surface, which is why the consent rail is the differentiating work, not the plumbing.

**AGENT-FIRST DESIGN** — Split: **human creates + attests, agent consumes by name.**
- CLI (human-gated): `speko voices clone --name amir --clip a.wav [--provider cartesia] --consent self|granted --json` → one consolidated command wrapping create → signed PUT → finalize → provision → poll, returning `{name, provisions:[{provider, voiceId, status}]}`. Refuse in non-interactive mode (piped stdin = the agent path per the CLI's own TTY split) unless `--consent` is explicit; print the FCC/TCPA warning. Typed error codes (`VOICE_CLIP_UPLOAD_MISSING`, `VOICE_CLONE_ALREADY_PROVISIONED`) already exist for branching.
- Agent read path: `speko voices --mine` listing provisioned clones; `speko audio speak --voice <cloneName>` resolving via provisions. ("Read me this diff in my voice" is the legitimate agent use case.)
- MCP: **deliberately no clone-creation tool, ever** — documented, so an agent mid-call-session can never mint a voice that sounds like a specific human.

**EFFORT** — M (SDK resource + consolidated CLI command; the 3-step clip dance wrapped as one call). **NEEDS-PLATFORM?** — No for basic clone/list/provision (API complete). **Yes** for: consent field (`consent_attested_at` + kind, enforced at API so dashboard and CLI both inherit), clone-name resolution in synthesize (failover-aware via `voice_clone_provision`), merging clones into `/v1/voices`.

**RISKS (highest of all five)** — FCC 24-17: cloned voices are "artificial voice" under TCPA; outbound calls with them need prior express consent of the **called party**, $500-$1,500/call. Worst interaction with our own rails: the mandatory AI-disclosure opener spoken **in a real person's cloned voice** is precisely the FCC's trusted-person-confusion scenario. Recommended policy before any call-path wiring: clones allowed for `speko audio speak` (local TTS), **blocked or self-voice-only on the calling path**, enforced platform-side. Also: ElevenLabs `requires_verification` is captured into provision metadata but never surfaced — a provisioned-but-unverified clone fails at synthesis with no explanation.

### 2.2 Emotion Tags / Expressiveness

**WHAT EXISTS**
- `EXISTS-platform-only` — Fully authored per-model capability registry: `TtsModelCapability {acceptsInstructions, supportsInlineTags, supportsSSML}`, conservative defaults (`packages/core/src/lib/model-capabilities.ts:50-79`). `supportsInlineTags` true for: eleven_v3 only ("v2.x render tags literally" per the platform's own comment), Cartesia sonic-3/3.5, all 5 Inworld models, MiniMax 2.6/02 (`packages/core/src/lib/types/api.ts:415-628`).
- `MISSING (platform)` — **The registry is dead metadata:** zero consumers of any capability flag anywhere in apps/server, worker-ts, or dashboard (grep-verified by two lanes independently). No tag stripping, no translation, no capability-aware routing.
- `MISSING (platform)` — `/v1/voices` drops capabilities when serializing: `models: p.models.map((m) => m.id)` — bare strings (re-verified this session, `apps/server/src/routes/voices.ts:~65`). No client can ask "does this model render [laughs]?"
- `MISSING (platform)` — No instructions transport: `TtsConfig` has no `instructions` field despite core doc comments referencing one (doc-vs-code drift, `pipeline.ts:64-77` vs `model-capabilities.ts:21-22`); `/v1/synthesize` schema has no instructions param (`synthesize.ts:45-56`); openai-tts adapter sends only model/voice/speed.
- `EXISTS-platform-only` — Inline tags **pass through verbatim today**: `speko audio speak "[laughs] hi" --provider elevenlabs --model eleven_v3` works with zero API change (`synthesize.ts:346-352`). But failover runners-up use their own selector models, so tag-laden text landing on eleven_flash_v2_5 or rime gets "[laughs]" **spoken aloud** — the B2-leak bug class, now structural.
- `UNVERIFIED / lane finding` — SPE-144's "Speko expressive emotion tags only Sonic-3.5 renders" has **no code counterpart** in server or worker-ts; tags lane concludes they must be prompt-level (agent system prompts emitting tags). Inferred, not confirmed with a prompt-side source.

**COMPETITOR BENCHMARK** — Three incompatible dialects: inline brackets (ElevenLabs v3 open-ended `[laughs]`; Cartesia `[laughter]` + `<emotion/>`; Inworld fixed list `[laughing]`), free-text instruction params (OpenAI gpt-4o-mini-tts, Hume, DashScope), SSML (Polly/Azure). Even laughter alone is `[laughs]` vs `[laughter]` vs `[laughing]` — raw pass-through is not portable across providers or failover.

**AGENT-FIRST DESIGN** — 3-tier ladder; the CLI becomes the capability-aware layer the platform lacks:
1. **Tier 1 (zero platform change beyond the 1-line voices fix):** expose `capabilities.{inlineTags, instructions, ssml}` per model in `speko voices --json`; document pass-through; CLI warns (or auto-pins) when text contains bracket tags and the resolved/possible model set includes tag-incapable models.
2. **Tier 2:** `--instructions/-i` flag once platform plumbs `TtsConfig.instructions` through route + SDK + 3 adapter mappings.
3. **Tier 3:** neutral declarative `--emotion excited --nonverbal laugh` schema translated per-provider dialect, stripped when unsupported.
Crucially, `--json` output must report **applied vs dropped** expressive controls (mirroring the existing provider/model/failover honesty line) so an agent detects degradation and retries pinned. Silent literal-tag speech is exactly the honest-outcome problem already fixed in the calls path.

**EFFORT** — Tier 1: S (given the voices.ts serialization change). Tier 2: M (4 layers). Tier 3: L. **NEEDS-PLATFORM?** — Tier 1 yes-but-tiny (serialize `m.capabilities` in voices.ts); Tier 2 yes (schema + TtsConfig + adapters); Tier 3 mostly client-side once 1-2 land. Also a platform decision: strip/translate tags on tag-incapable failover candidates, or exclude them from the chain when text contains tags (core docs at `api.ts:749-753` prescribe resolved-model evaluation; nothing implements it).

**RISKS** — Tags spoken literally on failover is a **shipping bug today** for anyone using tags — an agent has no way to even detect it. MiniMax's `supportsInlineTags` flag may mean "some inline markup" rather than bracket dialect (`api.ts:604-628`) — validate before building on it.

### 2.3 Failover Visibility

**WHAT EXISTS**
- `EXISTS-platform-only` — Chain = benchmark-ranked primary + `runnersUp` (default 4); caller's explicit model overrides only the primary; any attempt-open error advances the loop; `failoverCount` = loop index (`synthesize.ts:144-159, 316-391`).
- **Lane disagreement (resolved in favor of the precise version):** costs-failover lane said allowedProviders array order "has no meaning"; platform-truth lane found order IS honored in two edge paths — the pin-bypass path (explicit `vendor:model` pins with zero benchmark rows → ranked in pin order, `provider-selector.ts:452-490`) and the single-pinned direct path (`synthesize.ts:160-186`). Everywhere else it is a **filter, not an ordered chain** (`provider-selector.ts:87-115`). This nuance is exactly the trap: a naive `--failover a,b,c` CLI flag would be wrong.
- `EXISTS-platform-only` — Pre-flight chain is visible via `POST /v1/recommend-stack` `decisionTrace` (picks, runnersUp, axisScores, weightsUsed, candidatesFiltered — `recommend.ts:401-464`) but the SDK has no recommend resource (grep = 0 hits).
- `EXISTS-platform-only` — Server emits `X-Speko-First-Byte-Ms` (`synthesize.ts:226`); SDK drops it (re-verified this session: zero firstByte matches in installed dist). Per-attempt `attempts[]` is collected but only surfaced on total failure (`synthesize.ts:314-394`).
- `EXISTS-sdk` — `optimizeFor: balanced|accuracy|latency|cost` exists end-to-end incl. CLI `--optimize-for` — this is Speko's analog of Vercel's `sort:'cost'|'ttft'` and a positioning point, not a gap.

**COMPETITOR BENCHMARK** — Vercel AI Gateway returns the full per-attempt trace (`providerAttempts[] {provider, success, error, startTime, endTime}`) on **every** request plus caller-ordered `order[]`; OpenRouter `models[]` is an explicit priority list with the served model reported back. Speko exposes a single integer.

**AGENT-FIRST DESIGN**
- `speko recommend [--optimize-for cost] --json` over `/v1/recommend-stack` → ranked chain + why (decisionTrace) pre-flight.
- speak/transcribe `--json` gains `{firstByteMs, attempted:[{provider,model,error}], scoresRunId}` — all computed server-side today, discarded one layer up.
- Document loudly: `--providers` is a **filter**; order only matters for vendor:model pins with no benchmark rows. Agents will otherwise assume list order = retry order.
- Agent retry logic: `failoverCount=3` means the gateway already exhausted alternatives — don't blindly re-invoke; a per-attempt trace distinguishes "provider down" from "my input was rejected."

**EFFORT** — firstByteMs: S (SDK-only). recommend command: S/M (SDK resource + CLI, API exists). attempts-on-success: M (platform response change). **NEEDS-PLATFORM?** — firstByteMs no; recommend no (unless it's dashboard-only by intent — open question); per-attempt trace on success yes (`apps/server` synthesize/transcribe routes).

**RISKS** — Low. Main risk is design debt: building a caller-ordered failover flag on filter semantics.

### 2.4 Costs

**WHAT EXISTS**
- `EXISTS-sdk` — Per-**call** cost ships today: `CallReport.cost_micro_usd` + `cost_breakdown[{provider, metric, quantity, keySource, costMicroUsd}]`, `calls.report()` implemented (`packages/sdk/src/lib/types/index.ts:861-893`, `resources/calls.ts:28`; server `call-report.ts:149-165`). Also `usage.get()` → `{totalSessions, totalMinutes, totalCost, breakdown, balanceUsd}` and `credits.getBalance()/getLedger()` — **all unexposed in the CLI**.
- `EXISTS-platform-only` — Per-request cost is deterministic and computed **before the response closes**: `billableCostMicroUsd(metric, provider, quantity, keySource)`; µ$ table + MANAGED 7% markup (`MANAGED_KEY_MARKUP_BPS=700`), BYOK = $0; `recordUsage` writes usage row + ledger debit in one transaction (`pricing.ts:71-95`, `services/usage.ts:45-94`, `synthesize.ts:452-469`).
- `MISSING (platform)` — Nothing cost-related in synthesize/transcribe responses: no cost header (grep-verified), no request/generation id, route-level ledger debits have `sessionId=null` — per-op attribution is impossible; a CLI ledger-diff races with concurrent org traffic.
- `MISSING (platform)` — No budget caps beyond pre-flight balance>0 (`proxy-runner.ts:120-146`).
- Caveat (re-verified this session): pricing table comment reads "All numbers are editable placeholders — product must set real values before invoicing" (`pricing.ts:~15`). Whether current rates are display-safe is a product call, and inline cost surfaces the 7% markup that Vercel markets against ("0% markup").

**COMPETITOR BENCHMARK** — OpenRouter returns `usage.cost` inline in every response **by default** (the opt-in is deprecated — default-on won); Vercel returns `gateway.cost` + `generationId`; LiteLLM returns `x-litellm-response-cost` headers incl. margin, plus `max_budget`/`budget_duration` at 8 levels.

**AGENT-FIRST DESIGN** — Agents are budget-blind unless cost is in-band; polled aggregates never inform the next decision.
- Ship now: `speko usage`, `speko credits [ledger]` (pure CLI over existing SDK); `speko call report <id>` printing real cost + breakdown; MCP `get_call` result gains the report's cost (it currently omits it — `server/src/calls/getCall.ts:40-91`).
- Target contract: every `--json` result and MCP tool result carries `{costMicroUsd, balanceUsd}`; human line becomes `via cartesia:sonic-3 · failover 0 · $0.0012 · bal $4.98`.
- `--max-cost-usd` / `SPEKO_MAX_SPEND` client-side guard (LiteLLM pattern shrunk to CLI scope), interim via balance-diff with the race caveat, exact once the header lands.

**EFFORT** — CLI usage/credits/call-report: S. Per-op cost: S platform-side (header + `costUsd` in transcribe's done SSE event) + S SDK. Budget caps: M platform. **NEEDS-PLATFORM?** — Calls/aggregates no; per-op yes (`X-Speko-Cost-Micro-Usd` + `X-Speko-Key-Source` + request id on synthesize; `costUsd` in transcribe done event; stamping request id onto usage/ledger rows).

**RISKS** — Showing placeholder prices reads as a price promise; the 7% markup becomes user-visible the moment per-op cost ships. Needs product sign-off, not engineering work.

### 2.5 Diagram of Speech

**WHAT EXISTS**
- `EXISTS-sdk` — Per-turn wall-clock timing for calls is persisted and typed: `CallTranscriptEntry {index, source: user|agent|system, text, started_at, ended_at, provider, model}` (+`span_tree` on CallDetail) (`packages/sdk/src/lib/types/index.ts:849-859`; server `internal-turns.ts:14-27`, `call-report.ts:138-148`). **A turn-level who-spoke-when Gantt is buildable today, purely client-side.**
- `EXISTS-platform-only` — Word-level timestamps `{text, start, end, confidence}` are first-class in core `SttEvent.words` and emitted by 6 STT adapters (Deepgram, AssemblyAI, ElevenLabs, OpenAI, Google, xAI — `stt-provider.ts:10-28`, `deepgram-stt.ts:74-88`). The WS `/v1/transcribe/stream` route **forwards** them (`transcribe-stream.ts:463-480`); the batch SSE `/v1/transcribe` route **drops** them (done event carries only text/provider/model/confidence, `transcribe.ts:492-501`); SDK has zero `words` typing.
- `MISSING (platform)` — Per-turn latency legs (EOU delay + LLM TTFT + TTS TTFB per speechId) are computed in the LiveKit worker but only `console.info`'d to Cloud Logging — never persisted, no API can power a latency-breakdown diagram (`apps/worker-ts/src/agent.ts:592-616`).

**COMPETITOR BENCHMARK** — vercel-labs/ai-cli renders terminal waveforms via Kitty graphics with `--no-waveform` opt-out (our CLI already mirrors this); every serious STT vendor (Deepgram, AssemblyAI, ElevenLabs Scribe) treats word timestamps as a standard response field — Speko produces them and throws them away at one route.

**AGENT-FIRST DESIGN** — For an agent, "diagram" = **structured timing JSON**; ASCII/braille timeline is garnish for humans.
- `speko call transcript <id> --json` → per-turn `{source, text, started_at, ended_at, provider, model}` + optional `--diagram` ASCII Gantt (SDK data, zero platform work).
- `words[]` on `TranscribeResult` + CLI `--json`: SDK typing for the stream route (data already sent), one small server change for the batch route.
- Latency-leg diagram per turn: blocked on persisting the worker's EOU/TTFT/TTFB legs onto turn metadata.

**EFFORT** — Turn Gantt: S. Words: S (SDK) + S (platform batch route). Latency legs: M (platform, worker + schema). **NEEDS-PLATFORM?** — Turn diagram no; batch words yes (forward `SttEvent.words` in transcribe.ts done event); latency legs yes (worker-ts + turns persistence).

**RISKS** — Low. Only caveat: word-timing coverage across all adapters (cartesia/openai STT variants) should be verified before making `words[]` a hard contract field.

### Bonus findings (not in Bek's list, load-bearing for agents)

- **Concrete bug:** `speko audio speak` playback is gated on `isTTY && !values["no-play"]` (re-verified: `mcp/src/cli/audio/speak.ts:163`) with **no `--play` force flag** — the #1 agent use case (Claude Code Stop-hook speaking "build done") runs non-TTY, silently saves a file, never plays. One-flag fix.
- **No idempotency keys on dialing:** an agent retrying a timed-out `make_call`/`call_number` can double-dial a real business. Stripe pattern (client UUID, replay first result, 24h expiry) is the fix; needs platform support on the dial endpoints.
- **No AGENTS.md, no exit-code contract, no `--json` field selection/`--jq`** (gh CLI prior art) for the speko CLI.

## 3. Prioritized Roadmap (agent value × ship-now feasibility)

**Tier 0 — this week, zero platform changes, zero SDK bump (CLI-only in this repo):**
1. `--play` force flag on speak (fixes the hook use case; one line).
2. `speko usage` + `speko credits [ledger]` — SDK resources exist, unexposed.
3. `speko call report <id> --json` — real per-call cost + breakdown from `CallReport`.
4. `speko call transcript <id> --json [--diagram]` — per-turn timing + ASCII Gantt from `CallTranscriptEntry`.
5. MCP `get_call` result includes `cost_micro_usd` (data already in the report the server fetches).
6. Docs: AGENTS.md for the CLI; document `--providers` = filter-not-order; document tag pass-through + which models honor tags (static list from the core catalog until voices.ts exposes it).

**Tier 1 — SDK bump (platform API already exists):**
7. `SynthesizeResult.firstByteMs` (parse the header the SDK currently drops).
8. `speko recommend` over `/v1/recommend-stack` (new SDK resource; pending the "is it public?" answer).
9. `VoiceClones` SDK resource + consolidated `speko voices clone` — **consent-gated, TTY-required, `--consent` flag mandatory; no MCP clone tool ever.** Ship read path (`voices --mine`, `--voice <cloneName>` resolution client-side via provisions) alongside.
10. `words[]` typing for the WS transcribe-stream frames.

**Tier 2 — needs platform (small, surgical; owner ≈ apps/server routes / @abat's infra area):**
11. Serialize `m.capabilities` in `/v1/voices` (~1 line) → unlocks tag pre-flight for all clients.
12. `X-Speko-Cost-Micro-Usd` + `X-Speko-Key-Source` + request id on synthesize; `costUsd` in transcribe's done event; request id stamped onto ledger rows. (Blocked on the pricing-placeholder product decision, not on engineering.)
13. Forward `SttEvent.words` in batch `/v1/transcribe`.
14. Per-attempt `attempts[]` + tag applied/dropped status on success responses.

**Tier 3 — needs real platform design (name it, don't start it):**
15. Consent attestation field on `voice_clone` (mirror `demo_call.terms_accepted_at`) + clone-path policy for calls (recommend: blocked or self-voice-only).
16. Clone-name resolution inside synthesize via `voice_clone_provision` (makes clones failover-aware; without it cloning is decoration).
17. `TtsConfig.instructions` plumbing (route schema + SDK + OpenAI/Hume/DashScope adapter mappings).
18. Persist worker EOU/TTFT/TTFB legs onto turn metadata (latency diagram); idempotency keys on dial endpoints; per-key budget caps.

Opinionated call: **costs-on-report + call diagram + the --play fix are the week-one wins** — highest agent value, all data already typed in the SDK. Clone is the flashiest ask but the riskiest; ship its read path early and gate creation behind the consent design rather than racing it out.

## 4. Open Questions for Bek / Platform (decision-shaped, deduped)

1. **Pricing display:** pricing.ts says values are "editable placeholders — product must set real values before invoicing," and inline cost surfaces the 7% managed markup. Are current µ$ rates display-safe in a CLI, yes/no — and is the markup meant to be publicly visible?
2. **Cost header:** will apps/server accept `X-Speko-Cost-Micro-Usd` + a per-request id on synthesize/transcribe (cost is already computed pre-close; route ledger rows currently have `sessionId=null`)? Who owns that route change?
3. **Voices capabilities:** any reason `/v1/voices` can't serialize per-model `capabilities` (supportsInlineTags/acceptsInstructions/ssml)? It's ~1 line and unblocks all client-side tag validation.
4. **Tag contract on failover:** when tag-laden text fails over to a `supportsInlineTags=false` model, should the server strip/translate, exclude those candidates, or is client-side gating (CLI warns/pins) the intended layer? Today "[laughs]" gets spoken aloud.
5. **Clone consent + call policy:** will platform add a required `consent_attested_at` (+ kind) to clone creation before SDK/CLI exposure — and are cloned voices allowed on the outbound-call path at all (recommend: no, or self-voice-only), given FCC 24-17 makes a cloned voice to a non-consenting callee per-call liability?
6. **Clone consumption path:** is the intended design per-candidate resolution inside synthesize via `voice_clone_provision` (failover-aware clones), or provider-pinned raw voice ids? The table looks built for the former; nothing implements it. Also: is the surface even live in prod (`GCS_VOICE_CLIPS_BUCKET` set?) and does managed-key MiniMax cloning work (GroupId scoping)?
7. **Failover visibility:** is benchmark-ranked-only (caller cannot order the chain) a deliberate product stance vs OpenRouter/Vercel caller-ordered lists? If yes, can success responses at least carry the planned chain + per-attempt outcomes, and is `/v1/recommend-stack` public-SDK-intended or dashboard-only?
8. **Timing data:** green light to (a) forward `words[]` in batch `/v1/transcribe` like the WS route already does, and (b) persist the worker's per-turn EOU/TTFT/TTFB legs (agent.ts:592-616) onto turn metadata so call reports can power a latency diagram?
